## Why

foot renders 24-bit colour and says so: it exports `COLORTERM=truecolor` itself,
before any tracked file runs. The prompt takes it up — every `tide_*_color` in
`conf.d/tide.fish` is a hex value, and fish emits those as `38;2;R;G;B`. That is
why the prompt looks deliberate.

The two other large sources of colour at the prompt do not. `LS_COLORS` is built
in `conf.d/env.fish` from `dircolors -b`, whose codes are palette *indices*
(`01;94`, `00;36`), and fish's syntax highlighting is left at its built-in named
defaults (`red`, `brcyan`, `brblack`), which are indices too. Neither names a
colour; both ask foot to look one up in its 16 palette slots. So `ls` and the
command line render in whatever theme foot happens to ship — currently starlight
V4 — while the prompt renders in the colours this repository actually chose.

Setting `foreground=aaaaaa` could not fix that, and was never going to: the
default foreground is the colour used when *no* ANSI colour is selected. It
dimmed plain text and left every coloured thing exactly where it was.

Naming the colour outright also retires a workaround. `env.fish` currently
rewrites `01;3X` to `01;9X` across `LS_COLORS` to ask for the bright slots
outright, because herdr draws bold as weight rather than promoting the colour
and listings came out darker inside it. A `38;2;R;G;B` triple has nothing to
promote, so the discrepancy the rewrite exists to paper over cannot arise.

## What Changes

- `LS_COLORS` is generated by **`vivid`** from a theme tracked in this
  repository, instead of by `dircolors -b` plus the `01;3X` → `01;9X` rewrite.
  The theme names, as 24-bit hex, the same colours the listing renders today.
- The `fish_color_*` variables are set explicitly, to the hex equivalents of the
  named defaults fish uses now, so syntax highlighting stops resolving through
  palette slots. They go in a new `conf.d/colors.fish`, following the precedent
  `conf.d/tide.fish` sets for a prompt-appearance file outside the four named
  categories.
- `vivid` joins the **Optional** software the configuration reaches for: guarded
  by `type -q` like `direnv` and `fzf` are, silent when absent, with `LS_COLORS`
  falling back to the `dircolors` build so a machine without it still gets a
  coloured listing.
- foot's `[colors] foreground=aaaaaa` becomes tracked and specified rather than
  an uncommitted edit. Its comment is corrected: foot 1.27 defaults to `839496`
  foreground on `002b36` background, not the `dcdccc` the comment names — that
  was foot's default several major versions ago.
- The comment above the `COLORTERM` block in `env.fish` is corrected. It states
  that `TERM` is `xterm-256color`; under foot it is `foot`. The reasoning the
  comment gives is still right — terminfo cannot carry the answer and `TERM`
  travels over `ssh` — but it rests on a value that is not the one in play.

Explicitly **not** changed:

- `TERM` stays `foot`. `foot-direct` is the entry that carries `RGB` and
  `colors#0x1000000`, and setting it would put a terminfo name on the wire that
  far fewer hosts have than already fail to have `foot`.
- No local `~/.terminfo` override is compiled to add `RGB` to the `foot` entry.
  `COLORTERM` is the advertisement everything here reads.
- Consequently, programs that gate on terminfo rather than `COLORTERM` —
  `htop` is the one installed — stay at 256 colours. Accepted.
- No retheming. Every colour keeps the value it renders today.

## Capabilities

### New Capabilities

- `terminal-colors`: which colours the terminal and the programs running in it
  use, and by what mechanism they are named — direct 24-bit values rather than
  palette indices — so that what is on screen is what this repository chose
  rather than what the terminal's shipped palette happens to hold.

### Modified Capabilities

None. `shell-environment` already carries the requirement that 24-bit support is
*advertised* only where the terminal has it, and that requirement is unchanged:
this change is about what programs then emit, not about the advertisement.
`LS_COLORS` is named by no existing spec.

## Impact

- `.config/fish/conf.d/env.fish` — the `LS_COLORS` block is replaced; the
  `COLORTERM` comment is corrected.
- `.config/fish/conf.d/colors.fish` — new; the `fish_color_*` set.
- `.config/vivid/themes/starlight.yml` — new; the tracked vivid theme.
- `.config/foot/foot.ini` — the `[colors]` section, with a corrected comment.
- `.gitignore` — an allow entry for the vivid theme.
- `README.md` — `vivid` under **Optional**, with what its absence costs.
- `.bashrc` keeps its own copy of the environment block and builds `LS_COLORS`
  the same way; it gets the same treatment so bash sessions do not diverge.
- New machine-level dependency: `vivid` 0.11.1, absent from Fedora's
  repositories, installed from the `sharkdp/vivid` release tarball into
  `~/.local/bin`.
