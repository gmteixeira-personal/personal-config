## Why

The niri session opened alacritty on `Mod+T`, paying full terminal startup on every window. foot supports a server/client split that amortises that cost across a session, and it is already installed. Adopting it exposed two latent faults worth fixing at the same time: the compositor was started as a bare `niri`, so systemd's `graphical-session.target` never activated and no graphical user unit could ever autostart; and the login shell is bash, so a server started by systemd would hand every window bash rather than the fish actually in use.

Separately, several installed tools complete nothing under fish because their completions are neither built into fish nor derivable from a man page.

## What Changes

- The terminal bound to `Mod+T` becomes `footclient` instead of `alacritty`.
- `foot --server` is started for the graphical session through the packaged `foot-server.socket` and `foot-server.service` user units.
- Bare `niri` starts a session via `niri-session`, so the environment is imported into systemd and `graphical-session.target` activates. Subcommands (`niri msg`, `niri validate`) still reach the binary.
- foot gains a tracked `foot.ini` that names fish as the shell for new windows, independent of the login shell.
- fish completions are installed for `openspec`, `waybar`, and `npx`, which previously offered only filename fallback.

Not a breaking change: alacritty remains installed and launchable by name; only the keybinding moves.

## Capabilities

### New Capabilities

- `terminal-emulator`: which terminal the session opens, the server/client model it runs under, the shell it starts, and which of its configuration is tracked.
- `graphical-session-startup`: how the compositor is launched so that systemd's `graphical-session.target` activates, making graphical user units able to autostart at all.

### Modified Capabilities

- `shell-completions`: the spec covers only bash loading scripts from the per-user directory. It gains the fish side — that a tool lacking usable upstream completions is completable anyway, that a completion generated by its own tool is preferred over a hand-written one, and that only the hand-written ones are tracked — generated and harvested completions stay machine-local.

## Impact

- `.config/niri/config.kdl` — the `Mod+T` binding and its hotkey-overlay title.
- `.config/foot/foot.ini` — new file.
- `.config/fish/functions/niri.fish` — new file (already inside an existing allowlist rule).
- `.config/fish/completions/{openspec,waybar,npx}.fish` — new files. Only the two hand-written ones become tracked; the generated `openspec.fish` stays machine-local, as the ignore file's existing rule for that directory intends.
- The root ignore file — allowlist entries, since every path above except the fish function is currently caught by the deny-by-default `*` rule and cannot be tracked without one. The completion entries name individual files, to preserve that directory's machine-local default.
- Machine state outside the repository: two enabled systemd user units, and `~/.cache/fish/generated_completions/` populated by `fish_update_completions`.
- Prerequisite tooling installed during this work: the `openspec` CLI (npm, under the `~/.local` prefix, because the default global prefix is not writable) and `gh` from the Fedora repository.
