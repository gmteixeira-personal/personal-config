## Why

The fish right prompt drew a yellow `▼` (`tide_direnv_icon`, U+25BC) immediately to the left of the python item, so a prompt inside a project read `▼ 󰌠 3.14.7 (ycrm)`. The two marks report the same fact. On this configuration direnv has exactly one visible job — activating the virtual environment a project's `.envrc` declares — and the python item already names the interpreter version and the environment it came from. The `▼` adds a glyph without adding information, and it is the more cryptic of the two: it was mistaken for the prompt character in this very session, which is the sort of confusion an unexplained mark earns.

## What Changes

- Remove `direnv` from `tide_right_prompt_items` in the tracked `.config/fish/conf.d/tide.fish`. The right prompt then reports the environment once, through the python item.
- Keep the `tide_direnv_*` colour and icon variables. They are the item's appearance, not its presence; leaving them means re-adding the item later is one word in one list, with no glyph or colour to choose again.
- Nothing about direnv's behaviour changes. `conf.d/direnv.fish` still installs the hook, `.envrc` files still take effect on approval, and the environment still appears and disappears with the working directory.

### Modified Capabilities

- `python-venv-activation`: adds a requirement that the active environment is reported in the prompt, and reported once. The capability already governs when an environment is active and when it is not; it said nothing about how a shell tells you which state it is in, which is what left two indicators for one fact with no rule preferring either.

## Impact

- `.config/fish/conf.d/tide.fish` — one line changes, `tide_right_prompt_items`. The file is generated, so it is regenerated by `tide-save-config` rather than hand-edited, and the universal variable is set first so the dump does not write the old value straight back.
- `fish_variables` on this machine — `tide_right_prompt_items` and the derived `_tide_right_items` cache both lose `direnv`. That file stays ignored; it is the input to the dump, not the thing being shipped.
- No other tide setting moves. No `.gitignore` change — `conf.d/tide.fish` is already tracked. No README change — it already records that `conf.d/tide.fish` carries the prompt configuration.
- `conf.d/direnv.fish` is untouched, and so is the `python-venv-activation` machinery. Only what the prompt draws changes.
