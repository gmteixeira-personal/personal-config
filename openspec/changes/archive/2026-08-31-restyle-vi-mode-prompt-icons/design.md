## Context

See `proposal.md` — Why. The mechanics that shape the approach:

- tide keeps its settings as universal variables. `set -U` writes them to `~/.local/share/fish/fish_variables`, which this repository ignores as volatile machine state, so a universal alone never leaves the machine it was set on.
- `conf.d/tide.fish` exists to bridge that gap. It is generated by `functions/tide-save-config.fish`, which dumps every `tide_*` universal as a `set -g`. fish resolves a global ahead of a universal of the same name, so the tracked file wins over whatever the local wizard last stored — which is what makes the prompt configuration portable at all.
- That same precedence is a trap for editing. The file's header says not to edit it by hand, and `tide-save-config` reads universals, not the file, so hand-editing the file and then running the dump for any other reason would write the old values straight back over the edit.
- The glyphs are read by `functions/_tide_item_character.fish`, which fisher owns and rewrites on update. Nothing in the change may touch it.
- The committed file is currently byte-identical to a fresh dump of this machine's universals, verified before writing this. There is no accumulated drift for a regeneration to sweep in.

## Goals / Non-Goals

**Goals:**

- Land the new assignment such that the diff is exactly the two lines that changed.
- Land it through the mechanism the repository already documents, so the next person to run `tide configure` finds the same path still working.
- Leave this machine's universals and its tracked file agreeing afterwards, as they agree now.

**Non-Goals:**

- Reworking how prompt configuration is carried. The universal-dumped-to-global arrangement is not under review here.
- Adding the `vi_mode` prompt segment, or removing its `tide_vi_mode_icon_*` variables. It is undrawn and stays that way; deleting settings for an unused segment is churn with a rollback cost and no benefit.
- Choosing glyphs for anything else on the prompt.

## Decisions

**Set the universals, then regenerate — rather than editing `conf.d/tide.fish` directly.**

Editing the generated file is one step instead of two and would produce the same diff today. It is still wrong: it leaves this machine's universals holding `▚` for normal mode, so the next `tide-save-config` — run for an unrelated wizard change, months later — silently reverts this one. The two-step order is what keeps the file and the universals in agreement, which is the invariant the whole arrangement rests on. `tide-save-config` also drops the session's `tide_*` globals before dumping, precisely so the wizard's result is what gets read; setting universals first is the input that mechanism expects.

**Reassign only normal and visual.**

The alternative was picking a fresh set of four. Insert's `❯` is tide's own default and the glyph the user sees while typing; replace's `▶` is already a considered geometric shape distinct from the others. Changing either would enlarge the diff and the adjustment cost for no complaint being answered.

**`◆` for normal, `▚` for visual.**

`◆` (U+25C6) is solid, symmetric and unlike the two arrows, so normal mode — where the shell spends most of a session — is the shape that reads as "at rest, not inserting". `▚` (U+259A) moves rather than disappears: as a partial block it reads as a selection, which is what visual mode is, and it is the glyph the user already recognises from the prompt. Both are plain Unicode geometric shapes present in unpatched fonts, unlike the Nerd Font glyphs elsewhere in the tide configuration — the indicator keeps working in a terminal that has not been set up yet.

**Verify by driving the modes, not by reading the file back.**

The file is generated; that it contains the right lines says the dump worked, not that the prompt draws them. The requirement is about what appears at a prompt, so the check is pressing the keys that enter each mode in a real shell and looking.

## Risks / Trade-offs

- **A regeneration sweeps in unrelated universal drift.** → Checked before starting: the tracked file and a fresh dump are byte-identical, so the only lines that can move are the two being changed. The task list re-checks the diff after the dump rather than assuming it.
- **`▚` on visual mode is still the glyph the user called wrong.** → It was wrong for normal mode, not wrong in itself; on visual mode a half-block reads as a selection. If it still grates, the fix is a one-line reassignment through the same path.
- **The two-step order is easy to get backwards.** → Doing the dump before setting the universals writes the old values and looks like the change silently failed. The task list states the order, and the final check is the working-tree diff, which would show two unchanged lines if it were done wrong.
- **`◆` and `▶` are both solid dark shapes.** → They differ in silhouette and in colour (`tide_vi_mode_color_*` is not shared with the character, but the character's own colour tracks the last command's status, so the shapes carry the mode distinction alone). Read at a glance the diamond and the triangle are distinguishable; a caret-family glyph would be less so against `❯`.

## Migration Plan

Nothing to migrate. Other machines pick the change up on their next pull, and the tracked globals shadow whatever their universals hold, so no command has to be run there.

Rollback is `git revert` of the commit, plus `set -U tide_character_vi_icon_default ▚; set -U tide_character_vi_icon_visual V` on any machine where the universals had been resynced — a machine that only pulled needs nothing.
