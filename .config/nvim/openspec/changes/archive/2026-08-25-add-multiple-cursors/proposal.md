## Why

Renaming a local variable, adding a prefix to a run of adjacent lines, or changing one field name across a handful of call sites in the same file are all edits the configuration currently answers with either a substitute command or a macro. Both work, and both are a poor fit for the case they are most often reached for: a small number of occurrences, visible on screen, where the user wants to see what is about to change before committing to it.

Multiple cursors covers exactly that gap. It is not a replacement for `:%s` — which remains better for a whole file, or for anything involving a pattern rather than a literal — and it is not a replacement for the LSP rename the tooling change already provides, which is better whenever the thing being renamed is a symbol the language server understands. It is the tool for the edits that are neither: too small to be worth a regex, and not semantic enough for a language server to have an opinion about.

## What Changes

- Install [vim-visual-multi](https://github.com/mg979/vim-visual-multi) as the multiple-cursors implementation, as a new file `lua/plugins/vim-visual-multi.lua`.
- Keep `<C-n>` as the primary entry point: pressing it on a word selects that occurrence and creates a cursor, and pressing it again adds a cursor at the next occurrence. This is the plugin's one unconditional mapping and the key nearly all of its documentation assumes.
- Keep the vertical and horizontal entry points at their defaults: `<C-Down>` and `<C-Up>` add a cursor on the line below or above, and `<S-Right>` / `<S-Left>` extend a selection under every cursor.
- **Move the plugin's own leader off `\`.** Its default is `\`, which is precisely what `lua/config/options.lua` declares as `maplocalleader`. The plugin's leader is set to `<leader>m` instead, so its prefixed commands become `<leader>mA` (select all occurrences), `<leader>m/` (start a regex search), `<leader>m\` (add a cursor at the cursor position), and the visual-mode equivalents.
- Leave the plugin's in-mode mappings — the keys that only exist once multiple cursors are active — at their defaults, including `<Esc>` to exit, `n`/`N` to move between cursors, and `q`/`Q` to skip or remove one. The one exception is the plugin's own Undo and Redo, which ship unmapped: they are bound to `u` and `<C-r>` while cursors are active, because ordinary undo unwinds a multi-cursor edit one cursor at a time and a single-press revert is what keeps a mis-aimed edit cheap to correct.

### Conventions this change follows

- **`<leader>m` is a prefix only and is never itself a mapping**, the same rule `<leader>f`, `<leader>c`, and `<leader>h` already follow, so it never waits out `timeoutlen`.
- **The plugin owns its own keymaps**, declared in its file under `lua/plugins/` and nowhere else.
- **`\` stays a real localleader.** Nothing in the configuration maps `<localleader>` today, and this change deliberately keeps that key unclaimed rather than letting a plugin quietly take a namespace the configuration had reserved.

Non-goals: replacing LSP rename or `:substitute`, remapping any of the plugin's in-mode keys beyond the Undo/Redo pair above, changing its highlight groups to match the colour scheme, and mouse-driven cursor placement (the plugin ships it disabled and this change leaves it that way).

## Capabilities

### New Capabilities

- `multiple-cursors`: Editing at several places in a buffer at once by placing multiple cursors — by matching occurrences of the text under the cursor, by extending vertically across lines, or by pattern — and applying the same edit at all of them simultaneously.

### Modified Capabilities

None. The keymap namespace this change extends was established by `add-editor-tooling` as a convention in its design rather than as a spec requirement, so adding a prefix to it changes no existing spec. `config-structure`'s rule that a plugin declares its own keymaps in its own file is followed, not altered.

## Impact

- **Files created**: `lua/plugins/vim-visual-multi.lua`. One file, one plugin, per the existing rule.
- **Files modified**: `lazy-lock.json`, regenerated by lazy.nvim on install. No existing `lua/` file is edited — in particular `lua/config/options.lua` keeps its `maplocalleader` line untouched, which is the point of moving the plugin's leader rather than the configuration's.
- **External dependencies**: none. vim-visual-multi is pure Vimscript with no binary, no build step, and no runtime beyond Vim 8 or Neovim.
- **Startup cost**: none at startup. The plugin is loaded by its entry-point keys, so an editing session that never starts multiple cursors never loads it.
- **Keys newly claimed**: `<C-n>` in normal and visual mode, `<C-Down>`, `<C-Up>`, `<S-Right>`, `<S-Left>`, and the `<leader>m` prefix. None of these is currently bound by this configuration. `<C-n>` is worth calling out specifically: blink.cmp also uses `<C-n>`, but only in insert mode, where this plugin does not map it, so the two do not collide.
- **Breaking**: none for existing behavior. `<S-Right>` and `<S-Left>` shadow their built-in meanings, which move by word in insert and select mode — those defaults are unmapped in normal mode, which is where this plugin claims them.
